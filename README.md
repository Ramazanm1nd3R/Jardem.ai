# Jardem.ai

Платформа-агрегатор экстренных служб Алматы: сайт, приложение гражданина, приложение экипажа и общий backend с собственным движком диспетчеризации — подбор экипажа, маршруты по дорожному графу города, учёт пробок и перекрытий.

> **Это демонстрационный прототип (дипломный проект).** Экипажи, вызовы и пробки смоделированы; с государственными службами платформа не связана. В реальной экстренной ситуации звоните **112** (103, 102, 101).

## Запуск

Нужны Docker, Node.js 20+, Flutter 3.41+.

```bash
make up              # собрать сайт и поднять кластер
make build-mobile    # собрать оба Flutter-приложения под web
```

| Адрес | Что там |
|---|---|
| http://localhost:8080/ | сайт с живой картой |
| http://localhost:8080/app/citizen/ | приложение гражданина |
| http://localhost:8080/app/responder/ | приложение экипажа — логин `smp7`, PIN `1234` |
| http://localhost:8080/api/docs | описание API |

Симуляция по умолчанию идёт в 3 раза быстрее реального времени (`JARDEM_SIM_SPEED`), чтобы поездка в 6 минут занимала 2 минуты демонстрации. Остальные параметры — в `docker-compose.yml`.

## Как подбирается экипаж

Для всех открытых вызовов одновременно решается задача о назначениях: минимизируется время в пути с учётом пробок, взвешенное по срочности вызова. Для некритических вызовов добавляются штрафы за оголение района и за отправку специализированной бригады на рядовой вызов. Экипаж, который уже едет, перенаправляется только при ощутимом выигрыше. Две базовые стратегии — «ближайший по прямой» и «минимальное время в пути» — реализованы рядом для сравнения.

Результат сравнения на одинаковых смоделированных сценариях (3 прогона по 2 часа, среднее время до прибытия первого экипажа):

| Сценарий | nearest | min_eta | jardem |
|---|---|---|---|
| Обычная нагрузка | 5:52 | 5:43 | 5:45 |
| Час пик | 9:00 | 8:28 | 7:52 |
| Пиковая нагрузка, 60% парка | 25:57 | 25:25 | 17:23 |

При спокойной обстановке стратегии равны; выигрыш появляется, когда вызовы конкурируют за экипажи. Это свойства модели, а не измерения реальных служб.

## Чего в прототипе нет

- интеграции с 112, eGov и ведомственными системами;
- настоящих данных о пробках — только модель и скорость экипажей из приложения;
- настоящей идентификации пользователей (вход по номеру без SMS, общий PIN для служб);
- веб-консоли диспетчера (API для неё есть: `/api/v1/dispatch/*`);
- LLM-разбора обращений, голосового ввода, помощника первой помощи — разбор текста сделан правилами;
- публикации в App Store / Google Play.
